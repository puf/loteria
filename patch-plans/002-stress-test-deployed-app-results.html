N=90: hit a real external limit, not an app bug

Google's Identity Toolkit rate-limits anonymous sign-ups from a single IP (TOO_MANY_ATTEMPTS_TRY_LATER). This test session had already created ~90 anonymous accounts across the 5/10/25/50 tiers plus earlier verification testing, and the N=90 run tripped the limit after only 9 of 90 sign-ups.

Frank confirmed N=50's clean result is sufficient -- no retry was pushed through to force a clean N=75/90 data point.

Worth knowing for a real event: many phones joining in quick succession from behind the same conference WiFi NAT could plausibly trip this same Google-side limit, independent of anything in this app or the Firebase Spark plan's 100-connection cap. This test demonstrated the app's own scaling is fine -- it did not demonstrate sign-up-burst behavior from a shared IP, which is worth a quick real-device check closer to an actual event.
